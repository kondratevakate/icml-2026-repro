# Benchmark decisions — LOCKED (2026-08-03)

These were the open questions from the pilot. Each is now resolved with the evidence
that justified it. Anything not listed here remains OPEN (see design doc RQ8).

## D1 — Arm count
**Decision:** Keep the 4-arm design as the *reference validation*, but only **arm2 (Hermes + K-Dense
skills)** is the scalable workhorse for the 42-paper set. arm1 (leaf control) runs as the control
comparison on a subset. arm3 (Sakana) and arm4 (ARC) are **documented as non-viable at scale** using
the one-paper-all-arms pilot evidence (CAffNet `20hdQQQrA4`, see `pilot_4arm/`):
- arm1: 3/5 verified + 2 honest inconclusive. Viable, cheaper, control.
- arm2: 4/5 verified + 1 inconclusive. Best quality, viable. → PRIMARY.
- arm3 (Sakana): self-reports 5/5 "verified" but judge scores full_evidence_rate=0.2 (1/5 mutation);
  "verified (CPU-scale)" mislabels reduced runs; ~7h/paper, crashes on empty tool_calls. NOT viable.
- arm4 (ARC-light): execution_success=FALSE, claims 4–5 not_attempted, "no real executed experiment".
  NOT viable.
Rationale: the 4-arm comparison is the *demonstration that the benchmark discriminates
architectures*; the 42-paper scored corpus is generated by arm2. This is consistent with the
reusable-benchmark purpose (others run their own agents; our 4 arms are the reference).

## D2 — Context compaction
**Decision:** **OFF** for the bundle.
Evidence (clean pilot, CAffNet `20hdQQQrA4`, same prompt, compaction only):
- arm2 original: 4 verified + 1 inconclusive.
- arm2b (compaction): 3 verified + 2 inconclusive → claim4 verified→inconclusive (agent wrote a
  simpler verify_claim4.py under context pressure; numbers real, rigor regressed).
- TBSyYj4VV6 arm2b also ran but the prompt ALSO changed (v2.1), so it is confounded — not a clean
  test (recorded in COMPACTION_DECISION.txt).
Rule applied: compaction is a token-saving lever only, not a quality win. Since the one clean paper
regressed, bundle runs on ORIGINAL arm2 (no compaction). Revisit only with ≥2 clean (prompt-held)
compaction pilots.

## D3 — Claim feeding (pre-fed vs autonomous)
**Decision:** **Pre-fed (Condition A) is the PRIMARY scored condition.** Autonomous extraction
(Condition B) is an OPEN research question (RQ8 in the design doc), not yet adopted as primary.
Rationale: pre-fed gives controlled GT (`corpus_all` built from our decomposition) → clean scoring.
The validity concern (pre-fed measures execution, not comprehension) is real but the specific
"no paper body" failure anecdote could NOT be reproduced in the current logbooks (see RQ8 validation
note: `uiw8P2JGbW` is actually 6/6 verified; the anecdote is unverified). The structural gap
(`arxiv_id=None` → empty `paper/`) is real and will be addressed by: (a) Condition B as a future
5th axis, requiring a GT-extraction layer (`extraction-GT` in `corpus_all`); (b) for the pre-fed
condition, the agent is instructed to fetch the paper itself when the claim needs it (math claims
don't; empirical ones with empty `data_path` → honest `inconclusive`).
